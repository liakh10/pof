Replacing the Verifier's view of amounts and the nullifier key with a zero-knowledge proof the program checks itself.

Phase 2: the zero-knowledge Verifier

Phase 1 asks you to trust the Verifier with the openings of the notes you disclose and with your vault's nullifier key (Trust points, item 1). Phase 2 removes that view. The holder's browser proves the same statement with a Groth16 proof, and the program checks the proof on chain. Nobody, including the operator, sees an amount, the nullifier key, the owner, the notes or their nullifiers.

The statement#

The circuit (zk/circuits/pof.circom, circom 2, BN254, the same Poseidon as Rings) proves that the prover knows 1 to N notes such that:

  • each commitment is a leaf of the Rings state tree under a state root the chain holds;
  • each nullifier is derived correctly from the note and the prover's nullifier key;
  • each nullifier is absent from the Rings nullifier tree under a nullifier root the chain holds (unspent);
  • the amounts, all in one asset, sum to at least the tier minimum;
  • each nullifier is escrowed to a revocation key: encrypted on Baby Jubjub so that the holder of that key, and only they, can recover it and show the spend to revoke_spent.

The public inputs are the two roots, the asset, the tier minimum, a context value that ties the proof to one certificate, the escrow key, and per note a tag and a ciphertext. The program rebuilds or checks each one.

Status: under review, not live#

Phase 2 is in development in zk/: the circuit (4 notes per proof), a development setup, the browser prover and the on-chain instruction certify_zk. It is not live. The third round of the internal security review found one Critical and three High findings in certify_zk (ZK-01 to ZK-04 in reports/audit.md); among them, a note spent long ago could prove "unspent" against an older nullifier root. The launch build of the pof program does not include certify_zk at all. Phase 2 arrives later as a program upgrade, only after those findings are fixed and re-reviewed and the public setup ceremony has run. No certificate today is issued by a proof: every live certificate comes from the phase 1 Verifier described in this paper. The zero-knowledge circuit page describes the circuit, the setup and the on-chain verifier in full; the changelog will record the upgrade when it ships.
